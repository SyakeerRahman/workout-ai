# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

CodeFlex AI: a Next.js 15 (App Router, React 19) app where a user has a voice call with a Vapi assistant, and the call produces a personalized workout and diet plan that is generated by Gemini and stored in Convex. Clerk handles auth. The `upstream` git remote is the original open-source project. `origin` is Syakeer's copy.

`README.md` holds the full setup guide (Clerk, Convex, Gemini, Vapi, Vercel). Keep it in sync when env vars, endpoints, or the Vapi tool contract change.

## Commands

| Task | Command |
|---|---|
| Next.js dev server (Turbopack, port 3000) | `npm run dev` |
| Convex backend (dev sync, regenerates `convex/_generated`) | `npx convex dev` |
| Production build | `npm run build` then `npm run start` |
| Lint | `npm run lint` |

- Run `npm run dev` and `npx convex dev` in 2 terminals. Changes under `convex/` do nothing until `convex dev` pushes them.
- There is no test runner and there are no tests.
- Never edit `convex/_generated/` by hand.

## Environment variables

Two separate places:

- **`.env.local` (Next.js):** `NEXT_PUBLIC_CLERK_PUBLISHABLE_KEY`, `CLERK_SECRET_KEY`, `NEXT_PUBLIC_CLERK_SIGN_IN_URL=/sign-in`, `NEXT_PUBLIC_CLERK_SIGN_UP_URL=/sign-up`, `NEXT_PUBLIC_VAPI_ASSISTANT_ID`, `NEXT_PUBLIC_VAPI_API_KEY` (Vapi public key), `CONVEX_DEPLOYMENT`, `NEXT_PUBLIC_CONVEX_URL`.
- **Convex deployment env (`npx convex env set NAME value`):** `CLERK_JWT_ISSUER_DOMAIN` (read by `convex/auth.config.ts`), `GEMINI_API_KEY` and `CLERK_WEBHOOK_SECRET` (read by `convex/http.ts`).

## Architecture

The core flow crosses 3 external services, and much of it is configured outside this repo:

1. `src/app/generate-program/page.tsx` starts a Vapi call with `vapi.start(NEXT_PUBLIC_VAPI_ASSISTANT_ID, { variableValues: { full_name, user_id } })`. `user_id` is the Clerk user ID.
2. The Vapi Assistant (configured in the Vapi dashboard, not in this repo) asks the questions. Then its `generate_program` API Request tool POSTs a flat JSON body to the Convex HTTP endpoint `/vapi/generate-program` on the deployment's `.convex.site` URL: `age, height, weight, injuries, workout_days, fitness_goal, fitness_level, dietary_restrictions` from the model, plus `user_id` as a static body field set to `{{user_id}}`. Vapi Workflows were retired on 2026-08-19, so do not reintroduce them. Vapi Function tools send a different `message.toolCallList` envelope that this endpoint does not parse.
3. `convex/http.ts` makes 2 Gemini calls (`gemini-3.6-flash`, JSON response mode, via the legacy `@google/generative-ai` SDK): one for the workout plan, one for the diet plan. It then passes each result through `validateWorkoutPlan` / `validateDietPlan`, which remove extra fields and convert `sets`/`reps` to numbers.
4. `api.plans.createPlan` sets all of the user's existing plans to `isActive: false`, then inserts the new plan as active. Only 1 plan per user is active.
5. When the call ends, the page redirects to `/profile`, which reads `api.plans.getUserPlans` with a live `useQuery`.

User sync: Clerk sends `user.created` / `user.updated` webhooks to `/clerk-webhook` in `convex/http.ts`. The handler verifies them with svix and calls `api.users.syncUser` / `api.users.updateUser`. The `users` table exists only because of this webhook. Plans reference users by Clerk ID string (`plans.userId`), not by Convex document ID.

### Things to know before changing code

- **Keep 3 plan shapes in sync.** The Gemini prompt JSON examples and validators in `convex/http.ts`, the `createPlan` args validator in `convex/plans.ts`, and the table in `convex/schema.ts`. The schema is looser: routine `sets`/`reps` are optional there, plus it has `duration`, `description`, and `exercises`. `createPlan` requires `sets`/`reps` and rejects the other fields.
- **Convex functions do not check auth.** `getUserPlans` takes `userId` as an argument and does not use `ctx.auth`. `/vapi/generate-program` accepts any POST. Route protection exists only in `src/middleware.ts` (Clerk protects `/generate-program` and `/profile`).
- **Providers:** `src/providers/ConvexClerkProvider.tsx` wraps the whole app (in `layout.tsx`, outside `<html>`) with `ClerkProvider` and `ConvexProviderWithClerk`.
- **Vapi client:** 1 shared instance in `src/lib/vapi.ts`. The generate-program page overrides `console.error` to hide Vapi's harmless "Meeting has ended" error.
- **Home page sample programs:** `USER_PROGRAMS` in `src/constants/index.ts` is static data, not data from the database.

## Styling

- Tailwind CSS v4 with no `tailwind.config`. Theme tokens are in `src/app/globals.css` (`@theme inline`, plus a `--cyber-*` color palette used through arbitrary values such as `var(--cyber-grid-color)`). Custom animations such as `animate-scanline` and `animate-sound-wave` are also defined there.
- shadcn/ui (new-york style, lucide icons). Generated primitives are in `src/components/ui/`. Add more with `npx shadcn@latest add <component>`.
- Path alias: `@/*` maps to `src/*`. Files in `src/` import Convex's API by relative path (`../../../convex/_generated/api`).
